# StepFun 语音记忆助手

语音链路比文本链路多两次失败点（转写、合成），记忆链路多一次（服务不可用）。本 Skill 的核心是**分层降级**：任何一环失败都要退到可用的一层，而不是整段失败或编造内容。

> 接口细节（模型名、音频格式、限额）以 StepFun 官方文档为准；本 Skill 只固定调用顺序与失败语义。

## 一、链路

```
用户语音
  → StepFun ASR（转写，带语言/时间戳可选）
  → 转写文本
  → PowerContext：resolve_scope_binding → search_memory
  → StepFun 对话模型（携带命中片段与 citation）
  → 回答文本
  → StepFun TTS（可选，按用户偏好音色/语速）
  → 语音 + 文本双通道返回
```

环境变量：`STEPFUN_API_KEY`、`POWERCONTEXT_MCP_URL`。密钥只放环境变量或凭据管理，不写进 Skill、示例与日志。

## 二、检索与写入时机

| 场景 | 操作 |
| --- | --- |
| 每次会话首次交互 | `resolve_scope_binding`（默认 Scope 显式 `allow_default: true`） |
| 用户提到「上次说的」「之前那个方案」 | `search_memory`（query 用转写后的原话，去掉「嗯/那个」等口语填充词） |
| 用户明确说「记一下」「以后都这样」 | `remember_memory` |
| 用户纠正既有偏好（音色、语速、称呼） | `revise_memory_entry` |
| 用户说某条过时 | `retire_memory_entry` |
| 日常闲聊、当前轮已够用 | 不检索、不写入 |

语音场景的写入阈值要更严格：转写有歧义（置信度低、同音词多）时**先复述确认**再保存，不要把 ASR 错误固化成记忆。

## 三、降级矩阵

| 失败点 | 处理 |
| --- | --- |
| ASR 失败/超时 | 返回「没听清，请再说一次或直接打字」，保留上一轮上下文，不猜内容 |
| 记忆服务不可用 | 本次回答按无历史模式，明确告知「这次没有用到历史记忆」 |
| 检索为空 | 如实说没有相关记录，不要扩大成全量列举 |
| 对话模型超时 | 返回已检索到的要点（带 citation），不生成新结论 |
| TTS 失败/额度不足 | 只返回文本，并提示语音不可用；文本必须是完整可用答案 |
| 429/限额 | 指数退避重试一次，仍失败则降级为文本并说明 |
| 长音频 | 分段转写，拼接时保留分段边界，避免跨段串话 |

## 四、语音特有的约束

1. **隐私**：默认不把原始音频、转写全文写入记忆；只保存可复用结论。用户明确要求保存原话时才存，并说明保存范围。
2. **引用**：回答涉及历史时，语音里读要点，文本通道同时附 citation 与版本，便于回查。
3. **可重复性**：同一句话重复请求（网络重试）要按同一 Scope 处理，写入用幂等键，避免重复条目。
4. **多说话人**：若转写带说话人分离，按说话人分别标注，不把 A 的偏好写进 B 的记忆。
5. **数值与专有名词**：金额、编号、模型名读回时逐字符校对，必要时在文本通道复述确认。

## 五、验收清单

- 断网时语音助手仍能返回文本答案（无历史模式）。
- 关掉 TTS 额度后，回答文本完整、无截断。
- 记忆不可用时，界面明确提示「未使用历史记忆」。
- 同一结论重复播报不产生重复记忆条目。
- 日志中不出现令牌、原始音频 URL、用户隐私字段。
