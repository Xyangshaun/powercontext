# 4.1 Dify DSL 说明

## 一、交付文件清单与导入顺序

| 顺序 | 文件 | 用途 |
| --- | --- | --- |
| 1 | `dify/aji-inn-chatflow.yml` | 主应用 DSL（Chatflow，9 个节点，唯一运行入口） |
| 2 | `dify/4.2-运行说明.md` | 环境、版本、依赖、完整启动步骤 |
| 3 | `dify/4.3-验证样例与运行证据.md` | 可执行的验证样例、预期结果、证据编号 |
| 4 | `dify/4.4-按依赖补充材料.md` | 依赖清单（本题无 seekdb、无插件、无知识库） |
| 5 | `dify/SKILL.md` | 附：PowerContext 工具契约（MCP 接入备选路径说明，不参与主流程） |

导入顺序固定为：**先准备 PowerContext 服务 → 再把服务地址写进 DSL 环境变量 → 导入 DSL → 改绑模型 → 发布**。DSL 中不包含任何真实地址或密钥。

## 二、适用版本与部署方式

- Dify：云版 `cloud.dify.ai`（DSL 版本 `0.3.0`，需 Dify ≥ 1.6；低于该版本导入会提示版本兼容警告，功能不受影响）。
- 部署方式：Dify 云版托管；PowerContext 为自建 HTTP 服务，通过公网隧道暴露给 Dify 访问（见 4.2）。
- PowerContext：`3.4.4`（MCP `initialize` 返回 `serverInfo.version` 实测值）。

## 三、应用结构（每个节点为什么存在）

```
开始
 └─ 解析记忆作用域   POST {POWERCONTEXT_BASE_URL}/v1/scope-bindings/resolve   body: {"allow_default": true}
     └─ 准备请求体    Code：取 scope_id；json.dumps 生成 search / remember 两条安全请求体
         └─ 条件分支  玩家原话包含「记住 / 记一下 / 记下来 / 别忘了」→ true
             ├─ true  → 写入记忆   POST /v1/memory/remember  {scope_id, kind:"kaizen", text:玩家原话}
             └─ false → 跳过写入
                 └─ 召回记忆   POST /v1/memory/search  {scope_id, query:玩家原话, limit:5, mode:"auto"}
                     └─ 整理命中   Code：把 hits 整理成 [n] text (entry_id=…) 与引用清单，并输出 mode / hit_count
                         └─ 掌柜作答   LLM：只允许使用命中片段，逐条标注 [n]
                             └─ 掌柜回话   Answer：LLM 正文 + 本轮记忆引用（含 mode / hits）
```

设计要点：

- **默认作用域跨会话稳定**，所以「第二次新建会话仍能翻旧账」是真实召回，不是会话内变量。
- **写入是显式触发**（关键词分支），避免每轮闲聊都污染长期记忆；这是可解释的规则，不是隐藏魔法。
- **应答末尾固定输出 `mode` 与 `hits`**，评审可直接看到这一轮 PowerContext 到底有没有参与、走了哪种召回。
- 所有 HTTP 调用的 JSON 请求体由 Code 节点 `json.dumps` 生成，玩家原话里出现引号也不会破坏 JSON。

## 四、导入后需要改绑的项（逐条）

1. **模型**：导入后打开「掌柜作答」节点，把模型换成你工作区里可用的 Chat 模型（DSL 占位为 `langgenius/openai/openai` + `gpt-4o-mini`）。若你的工作区没有该供应商，节点会提示模型不可用，改选即可。
2. **环境变量 `POWERCONTEXT_BASE_URL`**：在应用「环境变量」里填你的 PowerContext 公网基地址，例如 `https://<your-host>`，**不要带 `/mcp`、不要以 `/` 结尾**。三个 HTTP 节点都引用这一个变量，改一处即可。
3. **会话开场白与推荐问题**：可保留（与验证样例对应），也可按需改文案。
4. 不需要改：知识库（本应用未使用）、插件（本应用未使用）、工具节点（本应用未使用 MCP 工具节点，全部为 HTTP Request 节点）。
5. 若你要改用 MCP 接入（备选，非主流程）：在「工具 → MCP 服务」新增 Streamable HTTP 服务，URL 填 `{POWERCONTEXT_BASE_URL}/mcp`，然后按 `dify/SKILL.md` 的工具契约自行替换三个 HTTP 节点。主流程不依赖 MCP，评审按 4.2 走即可。

## 五、占位符清单（仓库内不出现真实值）

| 占位符 | 含义 | 填写位置 |
| --- | --- | --- |
| `https://<your-powercontext-host>` | PowerContext 公网基地址 | DSL 环境变量 |
| `<MODEL_PROVIDER>` / `<MODEL_NAME>` | 你的 Chat 模型供应商与模型名 | 「掌柜作答」节点 |
| `<DIFY_VERSION>` | 你的 Dify 版本 | 仅文档引用 |

## 六、已知限制

- 本 DSL 未使用 Embedding / Rerank；检索默认走 `auto`，无向量模型时服务端自动落到 `fts`，返回的 `mode` 会如实显示。
- 记忆写入按关键词触发，属于产品规则而非模型判断；如要改成「由 LLM 判断是否写入」，替换「条件分支」为参数提取节点即可。
- 演示用隧道地址是临时的，重启隧道后地址会变，需要同步更新环境变量。
