# 4.2 运行说明

## 一、作品：阿吉客栈 · 记仇掌柜

**玩法**：你走进一家叫「阿吉客栈」的黑店，掌柜是个记仇的小老头。你干了什么混账事，只要说一句「记住……」，他就写进账本；等你换一个新会话再回来，他能当场把你的旧账翻出来，还会把账本条目编号拍在你脸上。

**体验方式**：在 Dify 对话窗口里直接说话，不需要额外前端。三个可试的动作：

1. **记账**：「记住，我把你后厨的铜锅砸了个豁口。」
2. **换会话翻旧账**：新建一个对话，问「掌柜的，你还记得我上次干了什么吗？」
3. **空账本对照**：「我偷偷往你酒坛里兑了水。」（没说要记）→ 他不会被写进账本，也翻不出来。

**核心功能**：跨会话的持久记忆 + 带引用的回答。记忆不是塞在 Dify 会话变量里，而是存在 PowerContext 服务端，所以换会话、换浏览器、换设备都还在。

**分工**：

| 角色 | 承担 |
| --- | --- |
| Dify（必选） | 全部流程编排：作用域解析、条件分支、记忆写入/召回、上下文整理、模型作答、结果输出 |
| PowerContext（本题选用的指定技术） | 唯一记忆后端：`scope` 作用域、`remember` 写入、`search` 召回，返回带 `citation`（`entry_id` / `entry_version_id`）的命中结果 |
| seekdb | **未使用**（本题允许二选一，本作品只选 PowerContext，不声明 seekdb 分工） |

> 「技术真正参与」的证据不是连通性测试，而是：**每一轮回答末尾的 `hits` / `mode` / `entry_id` 都来自 PowerContext 的真实检索结果，且第二次会话能命中第一次会话写入的条目**。见 4.3。

## 二、运行环境与版本

| 项 | 值 |

| Embedding / Rerank | 未使用 |

## 三、从零启动（PowerContext 侧）

```bash
# 1) 进入仓库并装依赖（已有 .venv 可跳过）
cd ob2026/powercontext
uv venv --python 3.12 .venv
uv pip sync --python .venv/bin/python requirements.txt   # 或按 pyproject 安装

# 2) 启动 HTTP + MCP 服务（SQLite 存储，数据目录自选）
POWERCONTEXT_HOME=<YOUR_DATA_DIR> \
POWERCONTEXT_SERVER_HTTP_PORT=8787 \
.venv/bin/powercontext server run
# 看到 "Uvicorn running on http://127.0.0.1:8787" 即成功

# 3) 另开一个终端，把本机端口暴露到公网
#    macOS: brew install cloudflared
cloudflared tunnel --url http://127.0.0.1:8787
# 日志里会出现 https://<random>.trycloudflare.com —— 这就是 base URL
```

自检（应返回 `scope_id`）：

```bash
curl -s -X POST https://<your-host>/v1/scope-bindings/resolve \
  -H 'Content-Type: application/json' -d '{"allow_default":true}'
```

## 四、Dify 侧完整步骤

1. 打开 `cloud.dify.ai`，进入你的工作区。
2. 「工作室 → 创建应用 → 导入 DSL 文件」，选 `dify/aji-inn-chatflow.yml`。
3. 打开应用 → 「环境变量」，把 `POWERCONTEXT_BASE_URL` 改为你的公网基地址（不带 `/mcp`、末尾不加 `/`）。
4. 打开「掌柜作答」节点，把模型改绑到你工作区可用的 Chat 模型（DSL 占位为 OpenAI `gpt-4o-mini`）。
5. 「发布」应用，进入「预览」或公开访问入口。
6. **应用入口**：Dify 应用页面里的预览对话框（或发布后生成的公开访问 URL），按 4.3 样例逐条输入即可。

## 五、网络与资源条件

- Dify 云版必须能访问 `POWERCONTEXT_BASE_URL` 的 443/80 端口；本方案用 cloudflared quick tunnel 打通，无需公网 IP、无需入站端口映射。
- PowerContext 为单进程 + SQLite，内存占用 < 200 MB，无需 Docker、无需数据库服务。
- 隧道地址是临时的，进程重启后地址会变；演示期间请保持 `powercontext server run` 与 `cloudflared tunnel` 两个进程常驻。

## 六、鉴权说明（重要且如实说明）

- 演示环境使用 `ACCESS_MODE=disabled`，即 **HTTP/MCP 端点不校验令牌**，依靠随机、短期有效的隧道地址做访问控制。
- 如果开启 `AUTH_ENABLED=true`，服务端会强制进入 `enforced` 访问控制模式，而该模式需要额外的授权服务（Casbin/AuthZEN）才能解析制品归属；实测此时记忆读写会返回 `artifact_owner_pending`（`Access Control is unavailable.`）。因此本演示未启用 Bearer 令牌。
- 生产化建议：在隧道前加 Cloudflare Access 或反向代理做 Bearer 校验，再让 Dify 侧填写 `Authorization: Bearer <token>`（DSL 的三个 HTTP 节点支持 `authorization.type=api-key`）。

## 七、已知功能限制

- 无向量检索：检索请求虽带 `mode:"auto"`，服务端在没有 embedding 配置时落到 `fts`，回答末尾会显示 `mode=fts`。
- 记忆写入由关键词触发（「记住 / 记一下 / 记下来 / 别忘了」），不是模型自主判断。
- 记忆条目不设上限管理，长期使用需按 4.3 的重置步骤清理。
- 单轮回答限制 80 字，是本作品的风格设定，不是模型能力限制。
