# 4.4 按依赖补充材料

> 本文件回答「为了跑通 4.1 的 DSL，除了 Dify 本身还依赖什么、缺了怎么补」。
> 只写本方案真实使用/真实未使用的依赖，不罗列无关组件。

## 一、依赖清单

| 依赖 | 是否必需 | 本方案用法 | 缺失时的后果/替代 |
| --- | --- | --- | --- |
| Dify（cloud.dify.ai 或自建 ≥ 1.x） | 必需 | 运行 Chatflow | 无替代 |
| 一个大模型供应商（OpenAI 兼容 / OpenAI 官方） | 必需 | LLM 节点「掌柜作答」 | 导入后用任意可用供应商改绑，见 4.1「改绑清单」 |
| PowerContext（本仓库 `powercontext`，本机实测 1.5.1） | 必需 | 记忆写入/检索（HTTP REST） | 无替代；它承担全部跨会话记忆 |
| 公网可达的 HTTP 入口（隧道或反代） | 必需 | Dify 云端访问 `POWERCONTEXT_BASE_URL` | 若 Dify 与 PowerContext 同机自建，可直接填内网地址 |
| seekdb（`@oceanbase/seekdb-node` 1.4.0 + `mysql2`） | 非必需 | 仅 `server.mjs` 本地复刻的**降级账本**：PowerContext 不可用时写 seekdb，不再用内存数组 | 不装 seekdb 时，降级分支会如实报「记忆服务与本地账本都不可用」，主链路不受影响 |
| Dify 插件市场里的 MCP 客户端插件 | **不使用** | 改用 HTTP 请求节点直连 REST | 若评审要求走 MCP，见第三节替代路径 |
| Dify 知识库 / RAG | **不使用** | — | 记忆召回全部走 PowerContext，不做向量库兜底 |
| Docker | 非必需 | 本机未安装，直接用 Python venv 起服务 | — |

## 二、预置数据：无

- 仓库**不附带任何预置记忆**。4.3 的样例从「空账本」开始，写入由第一个人工输入触发。
- 唯一附带脚本 `reset-memory.sh`：把当前作用域里的记忆条目逐条 retire，便于重复演示。
  - 用法：`POWERCONTEXT_BASE_URL=https://<your-host> ./reset-memory.sh --dry-run` 先看将作废的条目，去掉 `--dry-run` 才真正执行。
  - 该脚本调用的是 `POST /v1/scope-bindings/resolve`、`POST /v1/memory/entries/list`、`POST /v1/memory/entries/retire` 三个公开接口，不写库、不改配置。
  - **状态：脚本已写，`entry` 字段名与 retire 载荷以真实响应为准；作者未在 Dify 侧完成整轮演示，脚本本身仅做过静态检查（未实测），如与你的版本响应不一致，按 4.3 第四节的手工 curl 命令逐条执行即可。**

## 三、如果评审要求走 MCP 而不是 REST（替代路径）

本 DSL 刻意用 HTTP 请求节点直连 REST，原因是：MCP 客户端插件需要在 workspace 内手工安装，无法随 DSL 一起导入，导入方会多一步且易失败。

若必须走 MCP：

1. Dify「插件」页安装 MCP 客户端插件（如 `MCP SSE / HTTP` 类插件）。
2. 新建工具授权，地址填：`https://<your-host>/mcp/`（PowerContext 的 MCP 路径为 `/mcp`）。
3. 鉴权：本演示环境为**无鉴权**。若你的部署开了 `POWERCONTEXT_SERVER_AUTH_ENABLED=true`，还需配置 AuthZEN/Casbin 授权服务，否则记忆接口会返回 `artifact_owner_pending`（`Access Control is unavailable.`），这一点在 4.2 第六节与 4.3 第六节均已如实记录。
4. 把「写入记忆 / 召回记忆」两个 HTTP 节点替换为对应 MCP 工具调用（`memory_remember` / `memory_search`），参数语义一致；scope 仍先由 `scope-bindings/resolve` 解析。

## 四、最小可复现环境（版本锚点）

| 组件 | 版本 |
| --- | --- |
| PowerContext | 1.5.1（`python /tmp/pcrun/serve.py`，即 `powercontext.server.cli.run`） |
| Dify | cloud.dify.ai（2026-11 当前线上版） |

### dify/ 本地复刻的依赖声明

`dify/package.json` 声明的是**真实可安装**的依赖，均可从 npm 正常解析：

```json
"dependencies": {
  "@oceanbase/seekdb-node": "1.4.0",
  "mysql2": "^3.11.5"
},
"optionalDependencies": {
  "@oceanbase/seekdb-node-linux-x64-gnu": "1.4.0",
  "@oceanbase/seekdb-node-linux-arm64-gnu": "1.4.0",
  "@oceanbase/seekdb-node-darwin-arm64": "1.4.0",
  "@oceanbase/seekdb-node-darwin-x64": "1.4.0",
  "@oceanbase/seekdb-node-win32-x64": "1.4.0"
}
```

平台二进制必须放 `optionalDependencies`：放 `dependencies` 会在非对应平台上触发 `npm EBADPLATFORM`，安装直接失败（600077 首次提测的失败原因就是这个）。

一键验证：

```bash
cd dify && npm i && npm test          # node --test，4/4 通过
POWERCONTEXT_BASE_URL=http://127.0.0.1:8787 npm run session   # 生成 docs/evidence/dify-workflow-*.{json,md}
```

## 五、网络前提

- cloudflared quick tunnel 的域名是随机且**重启即变**：每次重启都要回到 Dify 改 `POWERCONTEXT_BASE_URL`。
- quick tunnel 无 SLA，长时间空闲会断；演示前先 `curl` 一次 `POST /v1/scope-bindings/resolve` 确认活着。
- 若企业网络限制 `*.trycloudflare.com`，改用自建反代或 ngrok 固定域名。
