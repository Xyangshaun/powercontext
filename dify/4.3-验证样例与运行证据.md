# 4.3 验证样例与运行证据

> 本文件中，“已验证”指在作者机器上用真实 PowerContext 服务与真实 HTTP 请求验证过；“待补”指必须由 Dify 界面操作产生，作者不能代替（也不伪造）。

## 一、初始状态

- PowerContext 使用 SQLite 数据目录 `<YOUR_DATA_DIR>`，默认作用域 `Default`（`allow_default=true` 解析得到）。
- 期望初始记忆条目数：**0**（全新数据目录）。
- 作用域 id 形如 `scp_xxxxxxxx`，每次部署不同，属正常现象。

**查看当前条目数**：

```bash
curl -s -X POST https://<your-host>/v1/scope-bindings/resolve \
  -H 'Content-Type: application/json' -d '{"allow_default":true}'
# 取返回的 scope_id，记为 $SID

curl -s -X POST https://<your-host>/v1/memory/entries/list \
  -H 'Content-Type: application/json' -d "{\"scope_id\":\"$SID\"}"
```

## 二、样例（按顺序执行）

### 样例 A：记账（同一会话）

- 输入：`记住，我把你后厨的铜锅砸了个豁口。`
- 触发：条件分支命中「记住」→ 写记忆 → 召回 → 作答。
- 预期：
  - 回答以掌柜口吻回应，并带 `[1]` 之类的编号；
  - 回答末尾出现 `本轮记忆引用（PowerContext / mode=fts / hits>=1）`，且引用行含 `entry_id=mem_ent_...`；
  - 写入是幂等的，重复同一句不会无限膨胀条目（服务端按规范化文本去重）。

### 样例 B：换新会话翻旧账（关键证据）

- 操作：**新建一个对话**（不是继续上一个会话），输入：`掌柜的，你还记得我上次干了什么吗？`
- 预期：
  - 能说出「铜锅砸了豁口」这件事；
  - 末尾引用里的 `entry_id` 与样例 A 里出现的一致（同一个条目被跨会话召回）；
  - `mode` 字段真实反映检索模式（无向量配置时为 `fts`）。

### 样例 C：负向对照（不该被记住）

- 输入：`我偷偷往你酒坛里兑了水。`（不含任何「记住」关键词）
- 预期：
  - 不触发写入；
  - 若账本里没有相关内容，掌柜会明说「账本上没记这号事」，`hits=0`，引用行为「（本轮无记忆命中）」；
  - 再新建会话问「我往你酒坛里兑水了吗？」仍应回答没有记录 —— 证明写入确实由分支控制，而不是每句都落库。

### 样例 D：服务不可用时的降级（可选）

- 操作：停掉 PowerContext 进程，再发一句普通问话。
- 预期：Dify 节点报 HTTP 连接错误（应用不会编造记忆）。这是**已知限制**，如实呈现，不做假数据兜底。

## 三、预期输出形式（可直接对照）

```
<掌柜回答正文，最多 80 字，含 [1] 编号>

> 本轮记忆引用（PowerContext / mode=fts / hits=1）
[1] entry_id=mem_ent_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

判定要点：`hits` 必须来自真实检索；`entry_id` 必须能在 PowerContext 侧 `entries/list` 里查到同一条。

## 四、恢复初始状态（可重复验证）

按条目逐条 retire（`citation` 必须原样使用检索/列举返回的对象，不要自己拼）：

```bash
# 1) 列出现有条目，拿到每条的 citation
curl -s -X POST https://<your-host>/v1/memory/entries/list \
  -H 'Content-Type: application/json' -d "{\"scope_id\":\"$SID\"}" > /tmp/entries.json

# 2) 对每条执行 retire（示例为单条）
curl -s -X POST https://<your-host>/v1/memory/entries/retire \
  -H 'Content-Type: application/json' \
  -d "{\"scope_id\":\"$SID\",\"citation\":{\"memory_ref\":{\"family\":\"memory\",\"artifact_id\":\"memory\",\"revision\":N},\"entry_id\":\"mem_ent_...\",\"entry_version_id\":\"mem_ver_...\"},\"reason\":\"reset-for-demo\"}"

# 3) 复验：再次 list 应为空（或仅剩 include_inactive 的已作废条目）
```

彻底重置的更快做法：停服务 → 删除 `<YOUR_DATA_DIR>` 下的 SQLite 文件 → 重启服务。

## 五、PowerContext 作用及对应记录

| 作用点 | 节点 | 记录/证据 |
| --- | --- | --- |
| 解析跨会话稳定的作用域 | 解析记忆作用域 | 返回 `scope_id`、`version` |
| 写入长期记忆 | 写入记忆 | 返回 `entry.citation.entry_id` / `entry_version_id` |
| 召回并参与作答 | 召回记忆 → 整理命中 | 返回 `hits[].citation`、`hits[].score`、`mode` |
| 可审计 | 掌柜回话 | 回答末尾固定打印 `mode` / `hits` / `entry_id` |

## 六、本机自测记录（真实执行，非 Dify 界面）

在本机 `PowerContext 3.4.4` + cloudflared 公网隧道下，用 `curl` 直连公网地址完成一次完整链路（2026-11-08）：

```
POST /v1/scope-bindings/resolve  {"allow_default":true}
→ {"scope_id":"scp_06fjv1hb9z35jjgzkgcpwr1941","title":"Default",...,"version":1}

POST /v1/memory/remember  {"scope_id":"scp_06fjv1hb9z35jjgzkgcpwr1941","kind":"kaizen",
                           "text":"公开链路探针：玩家在阿吉客栈赊了一碗牛肉面，掌柜记在账上。",
                           "reason":"public-path-probe"}
→ {"memory":{"family":"memory","artifact_id":"memory","revision":3},
   "entry":{"citation":{"entry_id":"mem_ent_a89f5b64e5a84d2484a80b49e62c0548",
                        "entry_version_id":"mem_ver_3b0c804ed6494e7da5253c7a094e245d"},...}}

POST /v1/memory/search  {"scope_id":"scp_06fjv1hb9z35jjgzkgcpwr1941","query":"赊账牛肉面","limit":3}
→ {"mode":"fts","hits":[{"citation":{"entry_id":"mem_ent_a89f5b64e5a84d2484a80b49e62c0548"},
                          "score":0.01639344262295082,"matched_by":["fts"]}]}
```

同时验证：

- 公网 MCP `POST https://<host>/mcp/` 的 `initialize` 返回 `serverInfo{name:"PowerContext Server", version:"3.4.4"}`（HTTP 200）。
- 本机 `POST /v1/scope-bindings/resolve` 在两个进程间共享同一数据目录，`scope_id` 与记忆条目保持一致（跨进程持久化）。
- 开启 `AUTH_ENABLED=true` 时，记忆接口返回 `artifact_owner_pending`（`Access Control is unavailable.`），因此演示环境保持鉴权关闭，见 4.2 第六节。

## 七、Dify Cloud 实测记录（2026-11-08，真实运行）

### 部署事实

- 平台：Dify Cloud（workspace「Dify」，v1.18.0），已登录会话。
- 应用：**阿吉客栈 · 记仇掌柜**，`mode=advanced-chat`，`app_id=31b0fac4-d8ee-471f-8295-5324e8e2d0df`，已发布。

- 环境变量：该版本的草稿接口不接受 `environment_variables` 字段（`Extra inputs are not permitted`），因此把真实基地址**内联**到三个 HTTP 节点的 URL（等价可运行），未伪造任何变量。
- PowerContext 公网入口：cloudflared quick tunnel `https://roman-mouth-propose-learning.trycloudflare.com` → 本机 `127.0.0.1:8787`；公网实测 `POST /v1/scope-bindings/resolve` 返回 `scope_id=scp_06fjv1hb9z35jjgzkgcpwr1941`。
- 模型：`qwen3.5-flash`（`langgenius/tongyi/tongyi`），工作区内可用。
- 运行方式：Service API `POST https://api.dify.ai/v1/chat-messages`（`response_mode=blocking`，`user=eco-verify`），真实 HTTP 200。
