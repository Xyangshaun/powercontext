# 一页技术说明

## 模块结构

- `src/ingest.mjs`：读取 `specs/*.md`、`demo/todo/*.mjs` 的导出符号、`demo/todo/tests/*.mjs` 的用例名与正文，生成 384 维向量写入 seekdb 三张表 `specs` / `code_chunks` / `test_cases`。每次 ingest 先清空再写入，因此规格改动会被下一次导入完整覆盖。
- `src/context.mjs`：把任务描述向量化，在三张表分别做 `cosine_distance` 排序取 Top-K，拼成开发上下文；并从 PowerContext 读回该任务已保存的状态。
- `src/state.mjs`：任务状态（done/todo/verified）以 JSON 文本写入 PowerContext，读回时按 `task` 精确匹配并取 `at` 最新的一条。
- `src/db.mjs`：`seekdb.open()` 启动/复用本地引擎，返回 MySQL 协议端点；数据目录 `.data/seekdb`。
- `cli.mjs`：唯一调用入口（CLI），输入任务文本，输出 JSON 上下文。

## 上下文选择方式

1. 任务文本 → 本地哈希嵌入（字符二元组 + 英文词，FNV-1a 哈希到 384 桶，L2 归一化）。
2. 三张表各自按余弦距离升序取前 3，附 `distance` 便于核对相关性。
3. 输出中的 `source` 直接指向仓库内真实文件/符号或测试名，便于评审核对；规格更新后重新 `ingest`，输出随内容变化。

## 技术分工

| 技术 | 在本模块承担的作用 | 状态 |
| --- | --- | --- |
